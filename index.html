API Testing Suite: every case, every response, every status code

Live results

36 API test cases against a REST service, with 13 published as a walkthrough covering seven status codes. Each case shows the request it sends, the status it expected, the status the service actually returned, the response body, and whether it passed.

I built this with an AI team in Claude Code instead of the engineering team I would normally have. My job did not change: define the coverage, structure the test cases, set priority, set the boundaries of what gets tested and what does not, review what came back, and reject what was wrong.

I built this to keep the testing craft current and to work out how to put AI to real use inside it. Release management keeps me in the lead functions every day: reviewing tickets, chairing go/no-go, and deciding which defects get deferred and which block a release.

ShopSmart QA Automation Suite

Recorded test runs

A pytest suite covering desktop web, mobile web and native iOS. Playwright drives the web flows against a public practice site (automationexercise.com), and Appium drives the Sauce Labs demo app natively on an iPhone Simulator. 11 tests built on page objects and fixtures, with video recording on every run. Two unedited recordings are published, along with the 54 manual test cases the automation was written from.

I built this one myself. I set up VS Code, Playwright, Appium and Xcode on my own machine, found every element identifier by hand, and worked through the login failures and timeouts as they came, with AI helping me write and correct the code. The 54 test cases were written one at a time in TestRail before any automation existed, and I pushed the work up myself.

I wanted my automation skills current again, and to prove I could still do the work end to end rather than only manage people who do it. This is the hands-on counterpart to the API project.

SQL Data Validation: Core Banking Migration Suite

Live demo

An interactive validation suite for a core banking migration scenario: a legacy on-prem platform moving to a modernized one, with defects seeded on purpose. Seven checks across five categories: reconciliation, referential integrity, transformation, PII and security, and performance. The SQL runs in the browser against a real database, so you can read each check, run it, and write your own in the query playground.

I had two sample databases generated to simulate a migration, then worked out what needed validating and wrote the cases: reconciliation, orphaned records, transformation, PII exposure, index use. Claude helped me construct and fix the queries case by case.

I built this to refresh my data skills. A lot of organisations are moving off on-premises databases onto modernized platforms right now, and testing one means proving the data arrived complete and correct, that nothing was orphaned in the move, and that nothing sensitive was exposed on the way.
